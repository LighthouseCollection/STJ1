## One issue per agent
- An agent works on the one issue it was started for, comments for its PM, and ends itself with `/home/agents/kit/host/bin/agent.sh done`. The PM runs continuously and never ends itself.
- Claiming: the launcher labels the issue `team:<name>` and `status:in-progress`; the builder comments "claiming". The first claim wins; the launcher refuses a second builder.
- Builder branches: `<team>/<issue>-<slug>`; the PR description says `Closes #<issue>`. PR review gates review the PR's head read-only and record PASS, FAIL, or N/A with a reason as a PR review.
- Sign every comment with a last line `— <team> · <title>`, for example `— north · QA Engineer`; PMs sign `— <team> · PM`.
- **When the kit gets in the way.** If the guard, a launcher, the watcher or another kit tool stops normal work or behaves wrongly, never work around it. Run `/home/agents/kit/host/bin/agent.sh report "<what happened, and what you were doing>"`, which records it in the host's kit log, then say so on the issue for your PM. Members record the fix.

## Merging and releasing
- **Merge rights: PR-only.** Roles that merge: members only (on GitHub). With Self-merge, the builder turns on auto-merge (`gh pr merge --auto`) and GitHub merges once every required check passes, including the gate check. Review gates never merge. Until the required checks exist (gate G0), a member merges.
- **Releases:** The release role (not registered yet) opens the release PR; when it merges, CI tags and publishes or deploys. No agent pushes a tag.
- Read the result of every push, merge and deploy before reporting it.
